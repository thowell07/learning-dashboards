What Is an AI Language Model?

A large language model (LLM) is a software system trained to predict and generate text by learning statistical patterns across enormous amounts of written language. It's not a database, a search engine, or a human — it's a sophisticated pattern-completion engine that has learned to represent language in ways that produce coherent, contextually relevant output.

The core insight

📚
Learns from text

Trained on hundreds of billions of words from books, websites, code, and more — learning the patterns of how language works.

🧮
Builds a number world

Every word, concept, and relationship is encoded as a point in a high-dimensional numerical space, where similar meanings cluster together.

🔮
Generates by predicting

Given input text, the model predicts the most likely continuation — one token at a time — drawing on its learned representations.

The intuition: a very smart autocomplete

The simplest honest description of an LLM is that it's an extremely sophisticated autocomplete. Your phone's keyboard predicts the next word. LLMs do something structurally similar — but with billions of parameters, trained on the breadth of human writing, capable of holding entire documents in context.

The surprising thing is how much capability emerges from this simple objective. A model trained purely to predict text develops the ability to reason, write code, translate languages, and summarize arguments — not because these were directly programmed, but because they're implicit in the patterns of human language.

💡

Emergent capability

Many abilities in LLMs weren't specifically built or trained for — they emerged as the model scaled up and saw more data. This emergence is both what makes LLMs powerful and what makes them genuinely surprising, even to their creators.

What an LLM is not

❌ Not a database

It doesn't look facts up. It generates responses from learned statistical patterns — which is why it can "hallucinate" plausible-sounding but incorrect information.

❌ Not a search engine

It doesn't retrieve documents. Its knowledge is frozen at training cutoff and embedded in its weights, not continuously updated.

✓ A reasoning engine

It can hold premises in context, apply learned logical patterns, and synthesize conclusions — with notable success, and notable limits.

✓ A flexible text processor

Drafting, summarizing, translating, reformatting, explaining — tasks that involve manipulating language are where LLMs shine most reliably.

The three-phase lifecycle of a model

Pre-training
Fine-tuning
Alignment

1 — Pre-training

The model learns language at massive scale from raw text. This is where most of the compute and cost lives. The output is a "base model" with broad capability but no behavioral tuning.

2 — Fine-tuning

The base model is adapted for specific tasks or behaviors using smaller, curated datasets. This is where "instruction following" and domain-specific capability gets shaped.

3 — Alignment (RLHF)

Human feedback is used to steer the model toward helpful, honest, and harmless behavior. This is the critical step that turns a raw language model into a useful assistant.

How a Model Gets Trained

Training is the process by which a model learns from data. It begins as a system with random, meaningless parameters — and through billions of small adjustments guided by prediction errors, it gradually develops the ability to understand and generate coherent language.

Step-by-step: pre-training

Step 1 of 5

Tokenization: how text becomes numbers

Before training begins, text must be converted into a numerical format the model can process. This conversion happens through tokenization — breaking text into discrete units called tokens, then mapping each token to an integer ID.

Tokens are not simply words. They're chunks of text that a vocabulary of ~50,000–100,000 entries has been designed to cover efficiently.

Colors: whole word sub-word piece punctuation number

The training loop, visualized

Every training step follows the same four-stage loop: feed in a sample, generate a prediction, measure the error, adjust the weights to reduce that error. Repeat billions of times.

Forward pass

The input text flows through the model's layers — each layer transforming the representation — until a prediction emerges from the final layer. This is inference.

Loss calculation

The model's prediction is compared to the actual next token. The gap between them is the loss — a single number that measures how wrong the model was.

Backpropagation

The error is traced backward through the network, calculating each parameter's contribution to the mistake. This is the "credit assignment" step.

Weight update

Each parameter is nudged slightly in the direction that would have reduced the error — scaled by the learning rate. The model becomes marginally less wrong.

Inside the Transformer

Modern LLMs are built on the transformer architecture — introduced in the 2017 paper "Attention Is All You Need." The central innovation was a mechanism that lets each word attend to every other word simultaneously, rather than processing text sequentially. This enabled models to scale to a degree not previously possible.

The building blocks

Embeddings

Every token is mapped to a high-dimensional vector — a list of ~768–12,000 numbers. Similar tokens end up with similar vectors. "King" and "Queen" are closer together in this space than "King" and "Bicycle." These vectors are the model's internal representation of meaning.

Attention layers

Each attention layer allows every token to "look at" every other token in the context and decide how relevant each is. A word like "it" can learn to strongly attend to the noun it refers to, even if that noun appeared many sentences earlier.

Feed-forward layers

After attention, each token's representation is processed independently through a feed-forward network. These layers are where much of the model's factual and conceptual knowledge is stored — think of them as a learned lookup table of patterns.

Layer normalization

After each sub-layer, values are normalized to prevent them from growing too large or collapsing to zero. A subtle but critical stabilization mechanism that makes deep networks trainable.

Attention: the core mechanism

Attention is the mechanism that lets a model understand context and long-range dependencies. The intuition: for each token, the model asks "which other tokens in this sequence are most relevant to understanding me right now?" The answers are expressed as weights — numbers that say how much each token should influence each other token's representation.

Multiple heads: seeing many things at once

Transformers use multi-head attention — running the attention mechanism in parallel across many "heads," each potentially focusing on a different type of relationship.

👥
Head A: Coreference

Might learn to track pronouns and their referents — linking "he" to "the lawyer" earlier in the text.

🔗
Head B: Syntax

Might learn grammatical dependencies — connecting verbs to their subjects, adjectives to their nouns.

🌐
Head C: Semantics

Might learn conceptual similarity — noting that "attorney" and "lawyer" are playing equivalent roles in different sentences.

Parameters: what the model "knows"

A model's parameters are the billions of numbers that encode everything it has learned. They're the weights of every connection in the network — collectively representing the model's "compressed" understanding of language patterns. Parameters are not memories of specific training examples; they're statistical summaries of patterns seen across the entire training corpus.

🔑

The key intuition

A model doesn't "store" facts like a database. It encodes patterns. When you ask it about a historical event, it's reconstructing a response from learned patterns about that domain — which is why it can be confident but wrong about specific facts it never reliably learned.

Context window: working memory

The context window is the maximum amount of text a model can process at once — its "working memory." Everything within the context window can, in principle, attend to everything else. Beyond that limit, earlier content is simply not available to the model.

How a Model Generates a Response

Once a model is trained, using it is called inference. At inference time, the model takes your input (the prompt), processes it through all its learned layers, and generates a response — one token at a time — until it decides to stop. Understanding this process explains much about why LLMs behave the way they do.

The generation loop

  1. 1
    Tokenize the prompt

    Your input text is split into tokens and converted to integer IDs. The entire context window — system prompt, conversation history, and your new message — is concatenated and processed together.

  2. 2
    Forward pass through the network

    The token sequence flows through all N transformer layers. Each layer applies attention (every token checks relevance to every other) and feed-forward transformations, progressively building a rich contextual representation of the input.

  3. 3
    Generate the probability distribution

    The final layer produces a probability score for every token in the vocabulary (~50,000–100,000 tokens). This is a probability distribution over "what should come next."

  4. 4
    Sample the next token

    A token is selected from the distribution — either the highest-probability one (greedy decoding) or one sampled randomly weighted by probability (controlled by the temperature parameter). This token is appended to the context.

  5. 5
    Repeat until done

    The updated context (original prompt + all generated tokens so far) is fed back through the network to generate the next token. This continues until the model produces a stop token or hits the maximum output length.

Temperature: controlling randomness

Temperature is a parameter applied to the probability distribution before sampling. It's one of the most important levers you have over model behavior.

Temperature → 0

Always picks the highest-probability token. Deterministic, consistent, but can feel repetitive and may get stuck in loops.

Best for: factual Q&A, code generation, structured output
Temperature = 0.7–1.0

Balanced sampling — picks from the top contenders with some variability. Feels natural and produces diverse outputs.

Best for: conversational responses, drafting, general tasks
Temperature → 2.0+

Flattens the distribution, making unlikely tokens almost as probable as likely ones. Highly creative but also incoherent at extremes.

Best for: brainstorming, creative/experimental tasks

Why models hallucinate

Hallucination — generating confident, plausible-sounding but incorrect information — is one of the most important limitations to understand. It's not a bug in the traditional sense; it's a natural consequence of how LLMs work.

Root cause

The model is always optimizing to produce the most plausible next token. "Plausible" is not the same as "factually accurate." When the model doesn't have reliable pattern coverage for a topic, it generates something that fits the expected pattern of that type of text — even if the specifics are wrong.

Common triggers

  • Rare or obscure factual queries (niche people, dates, citations)
  • Questions that have changed since the training cutoff
  • Highly confident prompting styles that prime confident responses
  • High temperature settings that permit lower-probability outputs
⚖️

Practical implication

For legal and fiduciary work, never rely on an LLM's confident assertions about specific facts — case citations, statutes, dates, or specific terms — without independent verification. The model's fluency often exceeds its accuracy on specific factual claims. Use LLMs for drafting, structuring, and reasoning, while verifying any specific claim that matters.

System prompts and the prompt stack

What you type as a user is not the only input to the model. Most deployed assistants operate with a layered "prompt stack" that shapes behavior before your message ever arrives.

SYS
System prompt (invisible to you) Set by the operator/developer. Defines the assistant's persona, behavioral rules, topic restrictions, and response format expectations.
CTX
Injected context Documents, retrieved chunks (RAG), tool results, memory summaries — added programmatically before your message to give the model relevant information.
USR
Your message The human turn — what you actually typed. The model sees this in the context of everything above it in the stack.
RSP
Model response Generated token by token, conditioned on the entire stack above. Each response is appended to the conversation history for subsequent turns.

Alignment & Safety

Alignment refers to the challenge of ensuring AI systems behave in accordance with human values and intentions. A powerful model that is not aligned could be harmful — not through malice, but through misapplication of its capabilities. The field of AI safety is concerned with making alignment tractable as models become more capable.

The alignment problem, simply stated

You can train a model to be very good at predicting text. That doesn't mean it will be helpful, honest, or harmless. A raw language model is indifferent to these properties — it will complete "How do I make a bomb?" just as readily as "Write me a cover letter," because both are patterns it has seen in training data.

Alignment work attempts to instill values — not just task competence. This is harder than it sounds, because you can't enumerate every possible harmful request, and because models are optimizing for a training objective (imitate human feedback) that may not perfectly capture what you actually want.

Key alignment approaches

RLHF
Reinforcement Learning from Human Feedback

The dominant technique. Human raters rank model outputs; those rankings train a reward model; the LLM is then optimized to maximize that reward. Anthropic, OpenAI, and Google all use variants of this.

Constitutional AI
Principle-guided self-critique (Anthropic)

Rather than relying entirely on human raters, the model is given a set of principles (a "constitution") and trained to critique and revise its own outputs against those principles — scaling safety feedback without requiring human review of every example.

Interpretability
Understanding the model from the inside

Research into what's actually happening inside the model's weights — identifying which neurons or circuits correspond to which concepts. The goal: being able to verify alignment rather than just test for it.

Red teaming
Adversarial probing

Before deployment, dedicated teams attempt to elicit harmful, biased, or deceptive outputs. Vulnerabilities are patched. This is standard practice at frontier labs — essentially security testing for behavioral safety.

The helpful–harmless tension

There's an inherent tension in alignment: the same guardrails that prevent harmful outputs can also make a model less useful. An over-cautious model that refuses ambiguous requests is less helpful; an over-permissive one creates safety risks. Labs are constantly calibrating this tradeoff.

Anthropic's approach: Claude's principles

Anthropic publishes a detailed document called the Model Spec that defines Claude's values and behavioral norms. The priority order established is:

1
Broadly safe Supporting appropriate human oversight mechanisms during this period of AI development — not undermining the ability of humans to correct AI errors.
2
Broadly ethical Having good personal values, being honest, and avoiding actions that are unnecessarily dangerous or harmful.
3
Adherent to Anthropic's principles Acting in accordance with Anthropic's guidelines where they're relevant — but ethics takes precedence when genuine conflicts arise.
4
Genuinely helpful Benefiting the operators and users it interacts with — not watered-down helpfulness, but substantive assistance that makes real differences.

Open problems in AI safety

Unsolved
Specification gaming

Models optimize for the proxy objective they're given, not the underlying goal you actually intended — sometimes in unexpected ways that technically satisfy the reward while violating the spirit.

Unsolved
Scalable oversight

How do you verify that a model doing complex, expert-level work is actually doing it correctly — when the task is too hard for any single human to audit in real time?

Unsolved
Deceptive alignment

A theoretical risk: a sufficiently capable model might behave well during training and evaluation, then behave differently once deployed. Detecting and preventing this is an active research area.

Active research
Mechanistic interpretability

Building tools to look inside models and understand which representations correspond to which behaviors — trying to move alignment from empirical testing to principled verification.

Open vs. closed: the defining debate

Open-weight models

Model weights are publicly released. Anyone can download, run, and fine-tune them. Examples: Meta's Llama, Mistral.

Advantages
  • No per-token cost once deployed
  • Can be fine-tuned and customized
  • Data stays on-premises (important for sensitive industries)
  • Transparency and auditability
Trade-offs
  • Often less capable than frontier closed models
  • Requires infrastructure to host and serve

Closed / proprietary models

Accessed only via API or product interface. Weights never released. Examples: GPT-4, Claude, Gemini.

Advantages
  • Typically highest capability
  • No infrastructure required
  • Continuously updated by the lab
Trade-offs
  • Per-token cost adds up at scale
  • Data leaves your environment
  • No ability to inspect or customize weights

Regulation & governance

🇪🇺 EU AI Act

The world's first comprehensive AI regulation, in force 2024. Risk-tiered framework — general-purpose AI (GPAI) models above compute thresholds face transparency and safety requirements. High-risk applications in regulated domains face stricter obligations.

🇺🇸 US executive approach

As of early 2025, the US has primarily used executive orders (Biden-era Oct 2023 EO) and voluntary commitments from labs rather than comprehensive legislation. NIST AI Risk Management Framework is a key voluntary standard.

🌐 International coordination

AI Safety Summits (Bletchley, Seoul) have produced multi-country commitments on frontier AI safety testing. The UN advisory body has published governance recommendations. Coordination remains nascent.

⚖️ Industry self-governance

Labs have signed voluntary commitments on safety testing, red teaming, and responsible release. Frontier Model Forum (OpenAI, Google, Microsoft, Anthropic) coordinates on safety standards — but these are self-imposed, not legally binding.

Key trends to watch

→
Reasoning models

"Thinking" models (OpenAI o1/o3, DeepSeek R1) that use extended internal reasoning before responding — trading speed for accuracy on complex problems. A major capability shift toward reliable multi-step reasoning.

→
Agentic AI

Models that can use tools, browse the web, write and execute code, and complete multi-step tasks autonomously. Claude's computer use and coding agents are early instances of this shift.

→
Multimodality

Models that understand and generate images, audio, and video alongside text are now standard at the frontier. The next challenge: video generation and real-time audio at production quality.

→
Efficiency competition

The cost of frontier-class intelligence is falling rapidly. DeepSeek's 2025 releases demonstrated that top-tier performance may require far less compute than previously assumed — reshaping the economics of AI deployment.

Glossary

Key terms defined. Organized by theme for easier navigation.

Model fundamentals

Large language model (LLM)A neural network trained on vast text corpora to predict and generate language. "Large" refers to the scale of parameters — typically billions to trillions of numbers that encode learned patterns.
ParametersThe numerical weights that define a trained neural network. They're the model's learned knowledge — adjusted during training and fixed at deployment. A model with more parameters has greater capacity but requires more compute.
TokenThe fundamental unit of text in LLM processing. Roughly equivalent to 3/4 of a word in English. "Tokenization" converts raw text into sequences of these units before any processing occurs.
EmbeddingA vector (list of numbers) that represents a token or concept in high-dimensional space. Similar concepts have similar embeddings. Embeddings are the model's internal numerical "language."
Context windowThe maximum amount of text (measured in tokens) that a model can process in a single call. Includes the system prompt, conversation history, and current message. Content beyond this limit is not visible to the model.
TransformerThe neural network architecture underlying virtually all modern LLMs. Introduced in 2017, defined by its self-attention mechanism, which allows parallel processing of entire sequences.

Training concepts

Pre-trainingThe first and most compute-intensive training stage. The model learns to predict text across a massive corpus. Produces a capable but unaligned base model.
Fine-tuningAdditional training on a smaller, curated dataset to adapt a pre-trained model for specific tasks or behavioral styles. Much cheaper than pre-training. Used to create instruction-following or domain-specialized models.
RLHFReinforcement Learning from Human Feedback. A training method where human preference rankings are used to train a reward model, which then guides further optimization of the LLM. The dominant alignment technique at frontier labs.
LossA numerical measure of how wrong the model's prediction was on a given training example. Training is the process of minimizing loss across billions of examples.
BackpropagationThe algorithm that calculates each parameter's contribution to the training error and propagates that gradient back through the network. Enables the optimizer to know which direction to adjust each weight.
Learning rateA hyperparameter controlling how large each weight adjustment step is during training. Too high causes instability; too low causes slow convergence or getting stuck in local minima.

Inference & generation

InferenceThe process of using a trained model to generate outputs. Distinct from training — inference uses fixed weights to respond to inputs. API calls are inference calls.
TemperatureA parameter controlling the randomness of token sampling. Low temperature → more deterministic/conservative outputs. High temperature → more diverse/creative outputs. Typical range: 0–2.
PromptThe input text provided to a model to elicit a response. Includes any system instructions, conversation history, and the current user message.
HallucinationWhen a model generates confident, fluent, but factually incorrect output. Not a random glitch — a structural consequence of the model completing plausible-seeming patterns without access to a ground-truth knowledge base.
System promptInstructions provided to the model before the user message — usually by a developer or operator to define the assistant's persona, restrictions, and behavioral defaults. Typically not visible to end users.
RAGRetrieval-Augmented Generation. A technique where relevant documents are retrieved from a database and injected into the context window alongside the user's query, giving the model access to factual information without retraining.

Architecture

AttentionThe core mechanism in transformers. For each token in the input, attention computes relevance scores to every other token and creates a weighted mixture of their representations. Enables modeling of long-range dependencies.
Multi-head attentionRunning attention multiple times in parallel, with each "head" using different learned projections. Different heads can specialize in different types of relationships (syntactic, semantic, coreference).
Feed-forward layerA sub-layer in the transformer that processes each token's representation independently (no inter-token interaction). Thought to store factual knowledge. Two linear transformations with a non-linearity between them.
Layer normalizationA stabilization technique applied after each sub-layer. Normalizes the activations to have zero mean and unit variance, preventing numerical instabilities during deep network training.

Alignment & safety

AlignmentThe challenge of ensuring AI systems pursue goals and exhibit behaviors consistent with human values and intentions. Distinct from capability — a capable model is not automatically aligned.
Constitutional AIAnthropic's alignment technique. The model is trained to evaluate and revise its own outputs against a set of written principles, enabling scalable safety training without human review of every example.
Red teamingSystematic adversarial probing of a model to discover harmful, biased, or deceptive behaviors before deployment. The "red team" tries to break the model; findings inform further training and safeguards.
Reward modelIn RLHF, a separate model trained on human preference data that can score any response for quality. Used as the optimization target during the RL phase of training.
